Claude Code로 프레임워크 없는 정적 블로그(`md-blog`)를 만들면서, HTML/CSS/JavaScript가 각자 어떤 역할을 맡는지 다시 정리해봤습니다.

## HTML — 뼈대와 의미

HTML은 페이지의 구조와 의미를 담당합니다. 이번 프로젝트에서는 딱 두 개의 뼈대만 있으면 충분했습니다.

- `index.html`: 검색창, 태그 필터, 글 목록이 들어갈 빈 컨테이너
- `post.html`: 글 제목과 본문이 채워질 빈 컨테이너

실제 내용(글 목록, 본문)은 HTML에 미리 적어두지 않고, JavaScript가 나중에 채워 넣습니다. 즉 HTML은 "여기에 검색창이 있다", "여기에 목록이 들어간다" 같은 자리만 잡아주는 역할입니다.

## CSS — 보이는 방식

CSS는 같은 구조를 라이트/다크 두 가지 모습으로 보여주는 역할을 했습니다.

```css
:root {
  --bg: #ffffff;
  --text: #1a1a1a;
}
:root[data-theme="dark"] {
  --bg: #14161a;
  --text: #e6e8eb;
}
```

색상을 변수로 빼두면, 다크모드 토글은 `data-theme` 속성 하나만 바꾸면 되고 나머지 스타일은 전혀 건드릴 필요가 없다는 걸 체감했습니다. 반응형도 마찬가지로, `flex-wrap`처럼 CSS 자체의 능력을 쓰면 미디어쿼리를 최소한으로만 써도 모바일에서 잘 보였습니다.

## JavaScript — 동작과 데이터

JavaScript는 "정적 파일들을 실제 블로그처럼 동작하게 만드는" 접착제 역할이었습니다.

- `posts/manifest.json`을 읽어와 글 목록을 렌더링
- `.md` 파일을 fetch해서 마크다운을 직접 파싱 → HTML로 변환
- 검색어/태그로 목록을 필터링하고 URL에 상태 반영
- 코드블록 언어를 보고 문법 강조 적용
- 다크모드 선택을 `localStorage`에 저장하고 다음 방문에도 유지

프레임워크 없이 진행하다 보니, "라이브러리가 대신 해주던 일"을 하나씩 직접 만들어봐야 했습니다. 특히 마크다운 파서와 문법 강조기를 직접 구현하면서, 평소 당연하게 쓰던 도구들이 내부적으로 어떤 처리를 하는지 조금 더 이해하게 됐습니다.

## 오늘의 한 줄 정리

> HTML은 자리를 만들고, CSS는 모습을 입히고, JavaScript는 그 안에 데이터를 흘려보낸다.
