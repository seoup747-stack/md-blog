# 2048 게임 — 구현 명세 (spec.md)

## 1. 앱 개요

방향키/스와이프로 숫자 타일을 밀어 같은 숫자끼리 합쳐 2048을 만드는 퍼즐 게임. 네온 사이버펑크 테마로 재해석한 버전.

## 2. 게임 규칙

- 4x4 그리드에서 시작. 게임 시작 시 빈 칸 중 2곳에 랜덤 타일(2 또는 4) 배치.
- 방향키(↑↓←→) 입력 시 해당 방향으로 모든 타일이 이동 가능한 만큼 이동한다.
- 이동 중 같은 숫자 타일 두 개가 부딪히면 하나로 합쳐지며 값이 2배가 되고, 합쳐진 결과는 점수에 더해진다(합쳐진 타일 값만큼 가산, 예: 4+4 합체 시 점수 +8).
- 한 번의 이동에서 한 타일은 최대 한 번만 합쳐진다(연쇄 합체 방지 — 2,2,4 → 이동 방향에 따라 4,4가 되고 그 둘은 같은 턴에 다시 합쳐지지 않음).
- 보드 상태에 실질적인 변화(타일이 하나라도 이동/합체)가 있었을 때만 턴이 진행되어 새 타일이 하나 생성된다. 변화가 없으면(막힌 방향) 아무 일도 일어나지 않는다.
- 새 타일은 매 턴 빈 칸 중 무작위 위치에 생성되며, 확률은 2(90%) / 4(10%).
- 더 이상 이동도 합치기도 불가능한 상태(보드가 가득 찼고 인접한 동일 숫자도 없음)가 되면 게임오버.
- 타일 중 하나라도 2048에 도달하면 승리 메시지를 표시하되, 사용자가 "계속하기"를 선택하면 게임을 계속 진행할 수 있다(승리 메시지는 게임당 최초 1회만 표시).

## 3. 파일 구조

```
apps/2048/
├── spec.md       # 본 문서
├── index.html    # 게임 마크업 (보드, 점수판, 버튼, 오버레이)
├── style.css     # 네온 테마 스타일 + 애니메이션
└── game.js       # 게임 로직 (IIFE, 전역 오염 없음)
```

블로그 본체(`index.html`, `post.html`, `css/`, `js/`, `posts/`)는 일절 참조/수정하지 않는다. `style.css`에 필요한 네온 색상값은 `css/style.css`를 import하지 않고 `apps/2048/style.css`의 자체 `:root`에 동일 값(또는 유사 톤)으로 복제해 정의한다(완전 자체 완결 원칙).

## 4. UI 구성

- 상단 헤더: 게임 타이틀("2048"), 점수판 2개 박스 — `SCORE`(현재 점수), `BEST`(최고 점수, localStorage 저장), 그 옆에 "새 게임" 버튼.
- 중앙: 4x4 게임 보드 (반응형 정사각형, 뷰포트 폭에 맞춰 최대 폭 제한 — 예: `min(90vw, 420px)`).
- 보드 위에 오버레이(기본 숨김, `display:none`):
  - 게임오버 오버레이: "GAME OVER" 문구 + 최종 점수 + "다시 시작" 버튼.
  - 승리 오버레이: "YOU WIN! 2048 달성" 문구 + "계속하기" / "새 게임" 버튼 2개.
- 하단: 간단한 조작 안내 텍스트(데스크톱: 방향키, 모바일: 스와이프).

## 5. 조작 방식

- 데스크톱: `document`에 `keydown` 리스너 등록, `ArrowUp/Down/Left/Right` 처리 후 `e.preventDefault()`로 페이지 스크롤 방지.
- 모바일: 보드 요소에 `touchstart`/`touchend` 리스너 등록.
  - `touchstart`에서 시작 좌표(x, y) 저장.
  - `touchend`에서 종료 좌표와의 차이(deltaX, deltaY) 계산.
  - `Math.abs(deltaX)`와 `Math.abs(deltaY)` 중 큰 쪽을 이동 축으로 채택, 최소 임계값(예: 20~30px) 미만이면 탭으로 간주해 무시(오조작 방지).
  - 부호에 따라 방향 결정(deltaX > 0 → 오른쪽, deltaY > 0 → 아래 등).
  - 보드에 `touch-action: none`을 CSS로 지정해 스와이프 중 브라우저 기본 스크롤/줌 제스처와 충돌하지 않게 한다.
- 두 입력 경로 모두 동일한 내부 함수(`move(direction)`)를 호출하도록 통일한다.

## 6. 시각 디자인 방향

- 배경: 블로그와 통일된 딥블랙(`#0a0a14` 계열), 보드 배경은 살짝 밝은 톤(`#12121f`)에 네온 보더(옅은 시안 글로우).
- 빈 칸: 어두운 회색-보라 톤 셀, 은은한 inset 보더.
- 숫자 타일 팔레트(값이 커질수록 색과 글로우가 진해지는 네온 그라데이션):
  - 2, 4: 옅은 시안/화이트 계열, 약한 글로우
  - 8, 16: 시안(`--neon-cyan`) 계열, 중간 글로우
  - 32, 64: 마젠타/핑크(`--neon-pink`) 계열
  - 128, 256: 퍼플(`--neon-purple`) 계열
  - 512, 1024: 그린(`--neon-green`) 계열, 강한 글로우
  - 2048 이상: 옐로우(`--neon-yellow`) 계열 + 가장 강한 `box-shadow`/`text-shadow` 글로우, 살짝 펄스 애니메이션(`@keyframes pulse-glow`)으로 강조
  - 각 타일은 배경색을 어둡게 유지하고 글자색+보더+box-shadow만 네온 컬러로 강조해 CLAUDE.md의 "글로우 남발 금지" 원칙을 지킨다(과도한 발광으로 가독성을 해치지 않음).
- 폰트: 숫자는 굵게, 모노스페이스 폰트(블로그의 코드/메타 정보 폰트 스택과 통일감 유지).
- 애니메이션(간단한 CSS transition 수준):
  - 새로 생성된 타일: `transform: scale(0) → scale(1)` + `opacity` 페이드인.
  - 합쳐진 타일: 합체 순간 잠깐 확대되었다 원래 크기로 돌아오는 pop 애니메이션(`scale(1) → scale(1.15) → scale(1)`).
  - 타일 이동: 타일 DOM 요소를 보드 내 절대 위치(퍼센트 또는 px, row/col 기반 `transform: translate(...)`)로 배치하고, 위치 값이 바뀔 때 `transition: transform 100~150ms ease`가 자동으로 슬라이드 효과를 만들어내도록 한다.

## 7. 상태 관리 방식

### 7.1 로직용 상태
- `board`: 4x4 2차원 배열(`number[4][4]`), `0`은 빈 칸, 그 외 값은 타일 숫자.
- `score`: 현재 점수(숫자), `bestScore`: 최고 점수(숫자, localStorage와 동기화).
- `hasWonThisGame`: 이번 게임에서 승리 오버레이를 이미 보여줬는지 여부(불리언, 계속하기 선택 시 재표시 방지).

### 7.2 렌더링용 상태 (애니메이션을 위해 별도 관리)
- 각 타일을 `{ id, row, col, value, isNew, mergedFrom }` 형태의 객체로 추적하는 타일 리스트를 별도로 유지한다.
- `id`는 타일이 생성될 때 부여되는 고유 값이며, 이동만 하고 합쳐지지 않은 타일은 이동 후에도 동일 DOM 엘리먼트/`id`를 유지해 슬라이드 애니메이션이 자연스럽게 이어지도록 한다.
- 합쳐진 타일은 살아남는 쪽 타일에 새 `value`를 부여하고 `mergedFrom` 플래그로 pop 애니메이션 트리거, 병합되어 사라지는 타일은 이동 애니메이션 종료 후 DOM에서 제거한다.
- 새로 스폰된 타일은 `isNew: true`로 표시해 스폰 애니메이션을 트리거한 뒤 플래그를 해제한다.

### 7.3 이동 로직 (한 줄씩 압축 → 병합 → 압축)
공통 핵심 함수 `slideAndMergeLine(line)` (길이 4의 1차원 배열, 왼쪽으로 미는 기준으로 정의)를 만들고, 방향에 따라 보드를 회전/전치해서 이 함수 하나로 4방향을 모두 처리한다.

`slideAndMergeLine` 절차:
1. **1차 압축**: `0`이 아닌 값들만 순서 유지한 채 왼쪽으로 모은다 (예: `[0,2,0,2]` → `[2,2]`).
2. **병합**: 압축된 배열을 왼쪽부터 순회하며 인접한 두 값이 같으면 하나로 합치고(값 2배) 그 칸의 점수를 `score`에 가산, 병합된 칸은 다음 병합 대상에서 제외(연쇄 병합 방지 플래그 사용).
3. **2차 압축**: 병합 후 생긴 빈틈을 다시 왼쪽으로 압축해 길이 4로 맞춘다(부족한 칸은 `0`으로 채움).

방향별 매핑:
- `왼쪽`: 각 행에 그대로 `slideAndMergeLine` 적용.
- `오른쪽`: 각 행을 반전(`reverse`) 후 적용, 결과를 다시 반전.
- `위`: 보드를 전치(transpose, row/col 교환) 후 각 행(원래는 열)에 적용, 결과를 다시 전치.
- `아래`: 전치 후 각 행 반전 적용 후, 반전 취소 후 다시 전치.

이동 전/후 `board`를 깊은 비교해 변화가 있었는지 판단하고, 변화가 있을 때만 새 타일 스폰 + 렌더링 + 게임오버/승리 체크를 수행한다.

### 7.4 게임오버 판정
- 빈 칸이 하나라도 있으면 게임오버 아님.
- 빈 칸이 없으면, 모든 칸에 대해 상/하/좌/우 인접 칸과 값이 같은 쌍이 하나라도 있는지 검사 → 있으면 아직 이동 가능(게임오버 아님), 없으면 게임오버.

### 7.5 localStorage
- 키: `md-blog-2048-best-score` (블로그의 다른 localStorage 키와 충돌하지 않도록 앱 접두사 포함).
- 점수 갱신 시마다 `score > bestScore`이면 `bestScore` 갱신 + `localStorage.setItem`.

## 8. 블로그 본체에 대한 영향 범위

이 기능은 `apps/2048/` 폴더 안의 `index.html`, `style.css`, `game.js` 3개 파일만 새로 생성한다. `md-blog` 루트의 `index.html`, `post.html`, `css/style.css`, `js/*.js`, `posts/*`, `feed.xml` 등 기존 파일은 전혀 수정하지 않는다. (이후 "Embed" 단계에서 루트 `index.html`에 앱 카드를 추가하는 작업은 본 spec의 범위가 아니며, 별도 단계/승인을 거친다.)
