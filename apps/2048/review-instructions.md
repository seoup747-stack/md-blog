# Review 지침 (2048 게임)

당신은 이 md-blog 프로젝트의 **Review 서브에이전트**입니다. Build 서브에이전트가 만든 `apps/2048/` 결과물을 독립적으로 검증하세요. 당신은 Build를 수행한 에이전트가 아니며, 그 결과물을 의심을 갖고 다시 확인하는 역할입니다.

## 확인할 것
1. `apps/2048/spec.md`를 읽고, 실제 구현(`index.html`, `style.css`, `game.js`)이 명세를 충족하는지 항목별로 대조하세요 (게임 규칙, UI 구성, 조작 방식, 시각 디자인, 상태 관리/이동 로직, localStorage 키, 블로그 본체 미수정).
2. 코드를 직접 읽고 버그 가능성을 점검하세요: 이동/병합 로직의 경계 조건(빈 보드, 가득 찬 보드, 연쇄 병합 방지), 게임오버 판정, 승리 오버레이 1회성, localStorage 키 충돌 여부, 이벤트 리스너 중복 등록 여부.
3. 브라우저 도구(Claude_Browser 계열)를 사용할 수 있으면 실제로 `apps/2048/index.html`을 열어 다음을 확인하세요:
   - 방향키로 타일이 이동/병합되고 SCORE가 오르는지
   - 새 게임 버튼이 보드/SCORE를 리셋하되 BEST는 유지하는지
   - 모바일 폭(375px)에서 레이아웃이 잘리지 않는지
   - 콘솔에 에러가 없는지
   브라우저 도구를 쓸 수 없다면 정적 코드 분석만으로 판단하고, 그 사실을 review.md에 명시하세요.
4. md-blog 루트의 다른 파일(`index.html`, `post.html`, `css/`, `js/`, `posts/` 등)이 실제로 전혀 수정되지 않았는지 확인하세요 (git status나 diff로 확인 가능).

## 결과물
`apps/2048/review.md` 파일을 작성하세요. 다음을 포함:
- 검증 방법(브라우저 실사용 검증 여부 포함)
- spec.md 대비 충족/미충족 항목 목록
- 발견한 문제(있다면 심각도와 함께) — 문제가 있다면 **당신이 직접 수정**하고, 무엇을 어떻게 고쳤는지도 review.md에 기록하세요. (Build 서브에이전트가 만든 코드라도, Review 단계에서 발견한 버그는 당신이 고치는 것이 이 프로젝트의 방식입니다.)
- 최종 결론: "배포 가능" 또는 "추가 수정 필요"

review.md 작성 후, 최종 응답에도 결론과 수정한 내용이 있다면 그 요약을 포함하세요.
