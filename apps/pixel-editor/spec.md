# 픽셀 아트 에디터 — 구현 명세 (spec.md)

## 1. 앱 개요

16x16 격자에 도트를 찍어 픽셀 아트를 그리고, 완성된 그림을 PNG 파일로 내보낼 수 있는 미니 픽셀 에디터.

## 2. 기능 요구사항

- 16x16 격자(총 256칸)를 캔버스에 렌더링한다.
- **그리기(Draw) 모드**: 칸을 클릭하거나, 클릭한 채 드래그하면 지나가는 칸이 모두 현재 선택된 색으로 칠해진다(단발 클릭도 동작해야 함).
- **지우개(Eraser) 모드**: 그리기와 동일하게 클릭/드래그로 지나가는 칸을 지우되(빈 칸/투명 상태로 되돌림), 색을 칠하는 대신 지운다. 그리기 모드와 지우개 모드는 토글 버튼으로 전환한다.
- **Clear 버튼**: 확인 없이(또는 `confirm()` 한 번으로) 격자 전체를 즉시 빈 칸으로 초기화한다.
- **PNG로 저장 버튼**: 현재 격자 상태를 PNG 이미지 파일로 다운로드한다.
- 드래그 중 같은 칸을 여러 번 지나가도 반복 처리로 인한 성능 저하나 시각적 깜빡임이 없어야 한다.

## 3. 파일 구조

```
apps/pixel-editor/
├── spec.md       # 본 문서
├── index.html    # 마크업 (헤더, 팔레트/툴바, 캔버스, 하단 안내)
├── style.css     # 네온 테마 에디터 UI 스타일
└── editor.js     # 그리드 상태 관리 + 그리기/지우기/저장 로직 (IIFE, 전역 오염 없음)
```

블로그 본체(`index.html`, `post.html`, `css/`, `js/`, `posts/`)는 일절 참조/수정하지 않는다. `style.css`는 `css/style.css`를 import하지 않고, 필요한 네온 색상값(`--neon-cyan`, `--neon-pink`, `--neon-purple`, `--bg` 등)을 `apps/pixel-editor/style.css`의 자체 `:root`에 동일 값으로 복제해 정의한다(2048 앱과 동일한 자체 완결 원칙).

## 4. UI 구성

- **그리드 렌더링 방식: `<canvas>` 채택.**
  - 이유: (1) CLAUDE.md에서 이번 앱은 캔버스 API만으로 충분하다고 명시하고 있고, (2) PNG 내보내기 자체가 캔버스 픽셀 데이터를 기반으로 하므로 편집 화면도 캔버스로 그리면 "화면에 그리는 로직"과 "내보내기용으로 그리는 로직"이 `fillRect` 기반으로 거의 동일해져 코드가 단순해진다. (3) 드래그로 지나가는 칸만 다시 그리는 부분 렌더링(전체 256칸 대신 변경된 칸 1개만 `fillRect`)이 CSS grid의 256개 DOM 엘리먼트를 다루는 것보다 가볍고 직관적이다.
  - 캔버스 실제 해상도(`canvas.width`/`canvas.height`)는 `16 * CELL_SIZE`(예: `CELL_SIZE = 20` → 320x320)로 고정하고, CSS로 `width: min(90vw, 320px); height: auto;`(정사각형 유지)로 반응형 표시 크기를 조절한다. 표시 크기와 실제 해상도가 달라져도 마우스/터치 좌표는 `canvas.getBoundingClientRect()`와 `canvas.width / rect.width` 비율로 환산해 정확한 칸 인덱스를 구한다.
  - 캔버스에는 `image-rendering: pixelated;`를 지정해, CSS로 확대/축소되어도 경계가 흐려지지 않고 또렷한 픽셀 느낌을 유지한다.
- **색상 팔레트**:
  - 미리 정의된 스와치 목록(예: 검정, 흰색, 회색, 빨강, 주황, 노랑, 초록, 시안, 파랑, 보라, 마젠타/핑크, 갈색 등 12~16개) — 각 스와치는 작은 정사각형 버튼(`<button>` 또는 `<div role="button">`)으로 렌더링.
  - 커스텀 색상 선택용 `<input type="color">` 하나를 팔레트 옆에 배치. 값이 바뀌면 해당 색이 즉시 "현재 선택된 색"이 되고, 이후 그린 칸에 반영된다.
- **현재 선택된 색상/도구 표시**: 팔레트 상단(또는 옆)에 작은 미리보기 영역을 두어 현재 색상(hex 값 텍스트 포함)과 현재 도구(Draw/Eraser)를 함께 보여준다. 선택된 스와치와 선택된 도구 버튼에는 네온 글로우 테두리를 적용해 시각적으로 구분한다.
- **툴바**: "그리기(Draw)" / "지우개(Eraser)" 토글 버튼 2개(또는 하나의 토글 버튼), "Clear" 버튼, "Save PNG" 버튼.
- **하단 안내 텍스트**: 데스크톱은 "클릭 후 드래그로 칠하기", 모바일은 "손가락으로 문질러 칠하기" 정도의 간단한 조작 안내.

## 5. 조작 방식

- **데스크톱**: 캔버스에 `mousedown`/`mousemove`/`mouseup`(+ `mouseleave`로 캔버스 밖으로 나가면 드래그 종료 처리) 리스너를 등록.
  - `mousedown`: 좌표 → 칸 인덱스 계산 → 해당 칸을 현재 색/지우개로 칠하고, `isPainting = true` 설정, 마지막으로 칠한 칸 좌표 기록.
  - `mousemove`: `isPainting`이 true일 때만 좌표 → 칸 인덱스 계산, 직전에 칠한 칸과 다를 때만 그 칸을 칠하고 "마지막 칠한 칸" 갱신(같은 칸을 반복 계산/재도색하지 않아 불필요한 렌더링 방지).
  - `mouseup`(또는 `document`의 `mouseup`, 캔버스 밖에서 버튼을 뗄 경우까지 커버): `isPainting = false`.
- **모바일**: 캔버스에 `touchstart`/`touchmove`/`touchend` 리스너를 등록.
  - `touchstart`: 첫 번째 터치 좌표로 칸 계산 후 즉시 칠하기, `isPainting = true`.
  - `touchmove`: 이동한 터치 좌표로 칸 계산 후 이전과 다른 칸이면 칠하기. 스크롤/줌 제스처와 충돌하지 않도록 `e.preventDefault()`를 호출한다(단, 리스너를 `{ passive: false }` 옵션으로 등록해야 `preventDefault()`가 실제로 동작함에 주의).
  - `touchend`: `isPainting = false`.
  - 캔버스에 CSS `touch-action: none;`을 지정해 브라우저 기본 스크롤/핀치줌 제스처가 그리기 동작과 충돌하지 않게 한다(2048 앱과 동일한 원칙).
- 데스크톱/모바일 두 입력 경로 모두 동일한 내부 함수 `paintCellAt(clientX, clientY)`를 호출하도록 통일해, 좌표→칸 인덱스 변환과 도색 로직이 한 곳에만 존재하게 한다.
- 드래그 중 같은 칸을 여러 번 지나가도 "마지막으로 칠한 칸" 좌표를 기억해 동일 칸에 대한 중복 도색 호출을 건너뛰므로 성능 문제나 깜빡임이 없다.

## 6. PNG 내보내기 방식

- **내보내기 해상도 결정: 16배 확대한 256x256으로 저장한다** (실제 16x16 그대로 저장하지 않음).
  - 이유: 16x16 원본 그대로 PNG를 저장하면 대부분의 이미지 뷰어/에디터가 이를 화면에 띄울 때 자동으로 부드럽게(보간) 확대해버려 픽셀 경계가 뭉개져 보인다. 16배 확대해 각 도트를 16x16px 블록으로 미리 "구워서" 저장하면, 어떤 뷰어로 열어도 픽셀 아트 특유의 또렷한 사각 도트가 그대로 보존된다.
- **변환 절차**:
  1. 화면 편집용 캔버스와는 별도로, 내보내기 전용 임시 `<canvas>`(width=256, height=256, DOM에 삽입하지 않고 메모리상에서만 사용)를 생성한다.
  2. 이 임시 캔버스의 2D 컨텍스트에서 `imageSmoothingEnabled = false`로 설정해 확대 시 보간이 일어나지 않게 한다.
  3. 16x16 색상 상태 배열을 순회하며, 색이 채워진 칸은 `ctx.fillStyle = color; ctx.fillRect(col*16, row*16, 16, 16)`로 16x16 블록을 그린다.
  4. 빈 칸(색이 없는 칸)은 아무것도 그리지 않고 그대로 둔다 — 임시 캔버스는 처음부터 투명한 상태이므로, 빈 칸은 자동으로 PNG의 투명(alpha=0) 영역이 된다(배경을 흰색으로 미리 채우지 않음).
  5. `tempCanvas.toDataURL('image/png')`로 데이터 URL을 얻는다.
  6. 메모리상의 `<a>` 엘리먼트를 만들어 `a.href = dataUrl`, `a.download = 'pixel-art.png'`로 설정한 뒤 `a.click()`을 호출해 다운로드를 트리거하고, 즉시 참조를 해제한다(DOM에 남기지 않음).
- 이 다운로드는 사용자가 브라우저의 기본 파일 저장 동작(또는 다운로드 알림)을 통해 로컬에 저장하는 정상적인 흐름이며, 별도의 서버 업로드나 외부 전송은 전혀 발생하지 않는다.

## 7. 시각 디자인 방향

- **에디터 UI(팔레트/버튼/툴바)**: 블로그와 동일한 사이버펑크/신스웨이브 네온 톤을 따른다.
  - 팔레트 스와치: 기본 상태는 얇은 회색-보라 계열 보더, 선택된 스와치는 `--neon-cyan` 계열의 `box-shadow` 글로우 보더로 강조.
  - 도구(Draw/Eraser) 버튼: 비활성 상태는 어두운 배경 + 옅은 보더, 활성(선택된) 상태는 네온 글로우 보더 + 살짝 밝아진 배경으로 구분.
  - Clear/Save PNG 버튼: 블로그의 버튼 스타일(어두운 배경, 네온 보더, hover 시 `box-shadow`/`text-shadow` 글로우 강화)을 따르되, Clear는 경고성 톤(예: `--neon-pink` 계열 보더), Save PNG는 확정/성공 톤(예: `--neon-cyan` 또는 `--neon-green` 계열 보더)으로 구분해 오조작을 줄인다.
  - 전체 배경은 블로그와 통일된 딥블랙(`#0a0a14` 계열), 카드/패널 배경은 `#12121f`~`#16162a` 톤.
- **캔버스(그리드) 자체의 배경은 중립 톤 사용**: 네온 컬러가 아닌 흰색 또는 옅은 회색 계열의 체크보드 패턴(예: `#ffffff`/`#e6e6e6` 2x2 체커)을 빈 칸 배경으로 사용한다.
  - 이유: (1) 사용자가 실제로 어떤 색을 칠하고 있는지 정확히 인지하려면 주변 배경이 채도 높은 네온색이면 색상 대비/색 지각이 왜곡된다. (2) 체크보드 패턴은 이미지 편집 도구에서 "이 칸은 투명(빈 칸)이다"를 나타내는 보편적인 관례이며, PNG 내보내기 시 빈 칸이 실제로 투명 처리된다는 점과 시각적으로 일치해 사용자에게 정확한 기대를 준다. 격자선은 옅은 회색(예: `rgba(0,0,0,0.15)`)으로 최소한만 표시해 도트 경계를 구분하되 그림 자체를 가리지 않게 한다.
  - 캔버스를 감싸는 컨테이너(패널) 테두리에는 얇은 네온 글로우를 주어, 캔버스 배경은 중립을 유지하면서도 전체 화면 톤과의 통일감은 잃지 않게 한다.

## 8. 상태 관리 방식

- **그리드 상태**: 길이 256(16x16)의 1차원 배열(또는 16x16 2차원 배열) `grid`로 관리하며, 각 원소는 색상 문자열(hex, 예: `"#00f0ff"`) 또는 빈 칸을 의미하는 `null`이다.
  - 빈 칸(`null`)은 화면에서는 체크보드 배경으로 보여주고, PNG 내보내기 시에는 투명(alpha=0)으로 처리한다(흰색으로 채우지 않음).
- **도구 상태**: `currentColor`(문자열, 기본값은 팔레트 첫 색 또는 검정), `currentTool`(`'draw'` | `'eraser'`).
- **드래그 상태**: `isPainting`(불리언), `lastPaintedIndex`(직전에 칠한 칸 인덱스, 중복 도색 스킵용).
- **렌더링**: 상태 배열이 바뀔 때마다 전체 캔버스를 다시 그리지 않고, 변경된 칸 하나만 다시 그리는 것을 기본으로 한다(단, `Clear` 버튼 클릭 시에는 전체 배열을 `null`로 초기화한 뒤 캔버스 전체를 한 번에 다시 그린다).
- **실행취소(undo) 기능은 이번 범위에서 제외한다.** 사용자가 실수로 칠한 칸은 지우개 도구로 직접 되돌리는 것을 기본 UX로 한다.
- 그리드 상태는 페이지를 새로고침하면 초기화된다(localStorage 등에 저장하는 영속화 기능도 이번 범위에 포함하지 않는다 — 향후 확장 아이디어로만 남긴다).

## 9. 블로그 본체에 대한 영향 범위

이 작업은 `apps/pixel-editor/` 폴더 안의 `index.html`, `style.css`, `editor.js` 3개 파일만 새로 생성한다. `md-blog` 루트의 `index.html`, `post.html`, `css/style.css`, `js/*.js`, `posts/*`, `feed.xml` 등 기존 파일은 전혀 수정하지 않는다. 이후 "Embed" 단계에서 루트 `index.html`에 이 앱의 카드를 추가하는 작업은 본 spec의 범위가 아니며, CLAUDE.md의 미니 웹앱 워크플로우에 따라 별도 단계/승인을 거쳐 진행한다.
