# Review 지침 (픽셀 아트 에디터)

당신은 이 md-blog 프로젝트의 **Review 서브에이전트**입니다. Build 서브에이전트가 만든 `apps/pixel-editor/` 결과물을 독립적으로 검증하세요. 당신은 Build를 수행한 에이전트가 아니며, 그 결과물을 의심을 갖고 다시 확인하는 역할입니다.

## 확인할 것
1. `apps/pixel-editor/spec.md`를 읽고, 실제 구현(`index.html`, `style.css`, `editor.js`)이 명세를 항목별로 충족하는지 대조하세요 (기능 요구사항, UI 구성, 조작 방식, PNG 내보내기 방식, 시각 디자인, 상태 관리, 블로그 본체 미수정).
2. 코드를 직접 읽고 버그 가능성을 점검하세요, 특히:
   - 좌표→칸 인덱스 변환이 `getBoundingClientRect()` 비율을 정확히 반영하는지 (캔버스 표시 크기가 CSS로 320px가 아닐 때도 정확한지)
   - 드래그 중 캔버스 밖으로 나갔다가 다시 들어왔을 때, 또는 마우스 버튼을 캔버스 밖에서 뗐을 때 `isPainting`이 올바르게 처리되는지
   - `touchmove`의 `preventDefault()`가 실제로 스크롤을 막는지 (`{ passive: false }` 옵션 확인)
   - PNG 내보내기 시 빈 칸이 정말 투명하게 나오는지(흰색으로 채워지지 않는지), 색칠된 칸이 16배 확대되어 정확한 위치에 그려지는지
   - Clear 버튼 동작, 팔레트/커스텀 색상 전환이 `currentColor`에 올바르게 반영되는지
   - 이벤트 리스너 중복 등록 여부
3. 브라우저 도구(Claude_Browser 계열)를 사용할 수 있으면 실제로 `apps/pixel-editor/index.html`을 열어:
   - 팔레트 색상 클릭 → 캔버스에 드래그로 그려지는지, 실제로 선택한 색이 칠해지는지
   - 지우개 모드로 전환 후 칠한 칸을 지울 수 있는지
   - Save PNG 클릭 시 콘솔 에러 없이 다운로드가 트리거되는지 (실제 파일 저장까지는 확인 못해도 에러 유무는 확인)
   - 모바일 폭(375px)에서 레이아웃이 잘리지 않는지
   - 콘솔에 에러가 없는지
   브라우저 도구를 쓸 수 없다면 정적 코드 분석만으로 판단하고 그 사실을 review.md에 명시하세요.
4. `git status`/`git diff`로 md-blog 루트의 다른 파일(index.html, post.html, css/, js/, posts/, apps/2048/ 등)이 전혀 수정되지 않았는지 확인하세요.

## 결과물
`apps/pixel-editor/review.md` 파일을 작성하세요. 다음을 포함:
- 검증 방법(브라우저 실사용 검증 여부 포함)
- spec.md 대비 충족/미충족 항목 목록
- 발견한 문제(있다면 심각도와 함께) — 문제가 있다면 **당신이 직접 수정**하고, 무엇을 어떻게 고쳤는지도 review.md에 기록하세요.
- 최종 결론: "배포 가능" 또는 "추가 수정 필요"

review.md 작성 후, 최종 응답에도 결론과 수정한 내용이 있다면 그 요약을 포함하세요.
